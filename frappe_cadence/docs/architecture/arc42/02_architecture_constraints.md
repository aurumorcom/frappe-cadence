# 02 Architecture Constraints

This document outlines the technical, framework, and operational constraints governing [`apps/frappe_cadence/frappe_cadence/hooks.py`](apps/frappe_cadence/frappe_cadence/hooks.py:1).

## Technical Constraints

| Constraint | Category | Source / Details |
| :--- | :--- | :--- |
| **Frappe Framework Ecosystem** | Technical | Must run within a Frappe Bench environment on Python 3.10+ / 3.14 with MariaDB as the primary ORM database and Redis for queueing and caching. |
| **Required Frappe Apps** | Dependency | Depends directly on `frappe_controller`, `frappe_playbook`, and `crm` apps declared in [`required_apps`](apps/frappe_cadence/frappe_cadence/hooks.py:11). |
| **Whitelisted API Signatures** | Security | Whitelisted endpoints and webhooks (`optimize_callback`, `predict_callback`, `callback`) must declare explicit type annotations (`require_type_annotated_api_methods = True` in [`hooks.py`](apps/frappe_cadence/frappe_cadence/hooks.py:287)). |
| **Background Job Execution** | Infrastructure | All long-running or rate-sensitive operations must be managed via `frappe_controller` background queues configured in `controller_events`. |
| **Sift AI Webhook Format** | External Interface | Sift AI callbacks must conform to expected JSON schema definitions generated by [`get_annotation_schema`](apps/frappe_cadence/frappe_cadence/integrations/sift.py:41). |

## Conventions & Standards

- **Single-File Architecture Standard**:
  - Structural models maintain C1 System Context, C2 Container, and C3 Component files under `docs/architecture/c4/`.
  - Behavioral flows are isolated per trigger under `docs/architecture/bpmn/`.
- **Framework Naming Conventions**:
  - All diagram nodes strictly use framework-native namespaced entities (e.g. `FrappeCadence::doctype::Cadence`, `ExternalSystem::Sift_AI_API`).
